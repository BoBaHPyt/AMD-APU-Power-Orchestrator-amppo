# Техническое задание: AMPPO - AMD APU Power Orchestrator

## 1. Общее описание проекта

**AMPPO (AMD APU Power Orchestrator)** — легковесная системная утилита на Rust для тонкого управления питанием, лимитами и частотами процессоров AMD Ryzen архитектуры Zen 4 / Hawk Point и новее в Linux.

### 1.1 Назначение

Проект представляет собой более точную, предсказуемую и эффективную альтернативу `power-profiles-daemon` (PPD), предоставляя прямой контроль над интерфейсами ядра `sysfs` для APU AMD.

### 1.2 Ключевые преимущества

- **Энергоэффективность**: Позволяет уменьшить расход батареи по сравнению с `ppd power-saver`
- **Производительность**: Позволяет увеличить производительность по сравнению с `ppd performance`
- **Гибкость**: Более точное управление температурами и питанием за счет прямой работы с sysfs
- **Оптимизация для APU**: Учитывает особенности объединенного питания CPU и GPU, где высокие вольты увеличивают температуры значительно сильнее, чем на системах с раздельными чипами

### 1.3 Пример эффективности

При применении зарезанного профиля:
- Потеря одноядерной производительности: ~30%
- Потеря многоядерной производительности: ~10%
- Потеря производительности GPU: ~12%
- Потребление: 10-15Вт вместо 45Вт
- Температуры: ~60°C при 100% нагрузке только CPU или GPU (83°C и 25Вт под полной нагрузкой CPU+GPU вместе)

### 1.4 Тестированное оборудование

- **Основная платформа**: Honor Magicbook X16 Plus 2024 (32GB RAM / 1TB SSD)
- **Процессор**: AMD Ryzen 7 8845HS (Radeon 780M / Hawk Point)
- **Ожидаемая совместимость**: Все APU AMD Ryzen поколений Phoenix/Hawk Point (серии 7040/8040) и новее
- **Поддерживаемые ядра Linux**: v6.x и v7.x с активным драйвером `amd_pstate` и параметрами `amd_pstate=active`, `amdgpu.ppfeaturemask=0xffffffff`

## 2. Текущая архитектура

### 2.1 Структура проекта

```
amppo/
├── Cargo.toml          # Конфигурация сборки
├── example_config.json # Пример конфигурационного файла
├── Makefile            # Скрипты установки
├── amppo.service       # Unit-файл для systemd
└── src/
    ├── lib.rs           # Корневой модуль
    ├── config.rs        # Парсинг конфигурации
    ├── state.rs         # Состояние демона
    ├── protocol.rs      # Протокол IPC
    ├── hardware/
    │   ├── mod.rs       # Экспорт модулей
    │   ├── cpu.rs       # Настройки CPU
    │   ├── gpu.rs       # Настройки GPU
    │   └── platform.rs  # Настройки платформы
    └── bin/
        ├── daemon.rs     # Системный демон
        └── client.rs     # CLI клиент
```

### 2.2 Текущие возможности

#### 2.2.1 Архитектура
- **Zero-Cost Abstractions**: Чистый Rust без тяжелых библиотек
- **Атомарное управление GPU**: Учет транзакционной модели драйвера `amdgpu`
- **Безопасная валидация**: Проверка доступности регуляторов перед записью
- **Клиент-серверная архитектура**: Демон работает от root, клиент от пользователя

#### 2.2.2 Подсистемы

**CPU Settings (cpu.rs):**
- `turbo_boost`: Включение/отключение турбо-буста
- `energy_performance_preference`: Преference EPP (power, balance, performance)
- `scaling_governor`: Governor (powersave, ondemand, performance, etc.)
- `min_freq`: Минимальная частота CPU (кГц)
- `max_freq`: Максимальная частота CPU (кГц)
- `dynamic_epp`: Динамическое управление EPP

**GPU Settings (gpu.rs):**
- `card`: Номер GPU карты
- `gpu_freq_min`: Минимальная частота GPU (МГц)
- `gpu_freq_max`: Максимальная частота GPU (МГц)
- `vram_freq_min`: Минимальная частота VRAM (МГц)
- `vram_freq_max`: Максимальная частота VRAM (МГц)
- `is_set`: Флаг применения настроек

**Platform Settings (platform.rs):**
- `profile`: Профиль платформы ACPI (low-power, balanced, performance)

#### 2.2.3 Протокол IPC

- **Транспорт**: Unix Domain Socket (`/run/amppo.sock`)
- **Права**: 0o666 (доступ для всех пользователей)
- **Формат**: JSON через serde_json

**Запросы (DaemonReq):**
- `cmd: "start"` — применить текущий профиль
- `cmd: "toggle"` — переключить на следующий профиль
- `cmd: "current"` — получить текущий профиль

**Ответы (DaemonResp):**
- `modename: String` — имя текущего профиля
- `hook: Option<String>` — опциональный хук для выполнения

#### 2.2.4 Конфигурация

Формат: JSON
Путь: `/etc/amppo/config.json`

Структура:
```json
{
  "modes": [
    {
      "modename": "Имя профиля",
      "cpu_settings": { ... },
      "gpu_settings": { ... },
      "platform_settings": { ... },
      "hook": "опциональная команда"
    }
  ]
}
```

#### 2.2.5 Текущие команды CLI

```bash
amppo-cli start      # Применить текущий профиль
amppo-cli toggle     # Переключить на следующий профиль
amppo-cli current    # Показать текущий профиль
amppo-cli current --while N  # Циклический вывод каждые N секунд
```

#### 2.2.6 Состояние

Файл состояния: `/var/lib/amppo/state.json`
Содержит:
- `index_mod`: Текущий индекс профиля
- `current_mode`: Имя текущего профиля

### Приложение C: Структура каталогов

```
/
├── etc/
│   └── amppo/
│       ├── config.json       # Основная конфигурация
│       └── config.json.bak   # Резервная копия (опционально)
├── run/
│   └── amppo.sock            # Unix socket
├── var/
│   ├── lib/
│   │   └── amppo/
│   │       ├── state.json    # Состояние демона
│   │       └── backups/      # Резервные копии
│   └── log/
│       └── amppo.log         # Логи демона
└── usr/
    └── local/
        └── bin/
            ├── amppo-daemon   # Демон
            └── amppo-cli      # CLI клиент
```
